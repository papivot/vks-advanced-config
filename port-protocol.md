# VCF 9.1, VKS and VCF Automation ports and protocols

This document addresses the common ports and protocols that are required for the various components of the VCF 9.1 stack, including the Supervisor, VKS and VCF Automation, to work efficiently. The document is specific to the following stack -
- VMware Cloud Foundation 9.1 (vCenter, ESXi, NSX, SDDC Manager)
- Avi Load Balancer (as integrated with VCF 9.1)
- Supervisor and vSphere Kubernetes Service (VKS) (as shipped with VCF 9.1)
- VCF Automation (VCFA) 9.1, running on the VCF Management Services Platform (VMSP)
- VCF Operations 9.1 (including the collector, license server and VCF Operations for Networks)

The flows documented here were captured from a live environment and grouped by the component that initiates the communication. The document is divided into the categories/groups below. Each group is a set of ports and protocols for a specific part/group of the platform. All traffic flow should be considered bi-directional.

Additionally, while we have documented the traffic flow between individual IPs within a pool of IPs (that would be in the same subnet), firewall ports may not need to be opened for these flows. These are marked as "Optional" and are for documentation purposes only.

The platform can operate in a completely air-gapped environment. As highlighted in the flows, the Internet egress traffic would need to be replaced by relevant endpoints (such as an offline depot or container registries hosting images) in the air-gapped/firewalled environment.

> **Note:** Flows from a few networks that have not yet been identified (172.30.0.0/24, 172.16.24.0/24, 100.64.32.0/24, 172.31.0.0/24, 172.16.23.0/24, 172.16.6.0/24 and a few one-off addresses) have been parked in the **Unidentified** tab of the flow capture workbook. These mostly relate to the Supervisor workload network, Supervisor Services and VKS clusters, and will be added to this document once the networks are confirmed.
